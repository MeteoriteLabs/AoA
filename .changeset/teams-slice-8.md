Wire team-import flow (Slice 8) — YAML upload to preview to transactional cascade install:

- `teamImportService.preview(companyId, yamlContent)` — `server/src/services/team-import.ts`. Parses + Zod-validates the manifest via `parseManifest` (which already calls `validateManifest`), then SQL-filters for agent-name collisions across the company and missing skill deps. Filtering happens at the SQL layer with `inArray(agents.name, allNames)` and `inArray(companySkills.key, declaredSkills)` rather than a full table scan + JS filter — keeps the wire payload small even for companies with thousands of agents/skills. Returns `TeamImportPreview` with `members[]` (each carrying `existingAgentId` if a name collides), `skillsToInstall[]`, and passthrough `pluginsToInstall[]` / `workflowsToInstall[]` (v1 surfaces these in the response shape but the dialog only renders missing skills — see followups in PR body).
- `teamImportService.install(companyId, yamlContent, resolution)` — transactional cascade. Pre-transaction guards: refuses if any required skill is missing (`Cannot install — missing skills: ...`), if the manifest declares >1 leads, or if a team with the same slug already exists in the company (clear UX errors, not a generic unique-violation throw). Inside `db.transaction(async (tx) => ...)`: resolves agent collisions per the resolution map (`skip` / `replace` / `rename` / default-create), inserts new agents into `agents`, **immediately** links them to the parent department via `agentProjects` (Convention C-6 — `addMember` invariant requires dept membership before team membership; if a future "lite install" path skips this it'll silently break — worth a runtime invariant check, see followups), inserts the team row, links agents via `team_members`, scaffolds the coordination row via `teamScaffolderService(tx).scaffoldInitial(...)`. Returns `{ id, slug, name, parentProjectId }`.
- `teamImportsRoutes(db)` factory — `server/src/routes/team-imports.ts`. Two endpoints under `/companies/:companyId/teams/_imports/`. `POST .../preview` accepts multipart upload (`multer.memoryStorage()` 5MB limit) **OR** JSON body fallback (`{ yaml: string }`). `POST .../install` validates body via Zod (`yaml` + optional `resolution` map). Both gated with `assertCompanyAccess` + `assertRole("founder", "team_lead")`. **No try/catch — `HttpError`s propagate to the global middleware** (matches Slice 5/6/7 route style; correction P-1). Install logs `team.imported` activity with `{ teamId, slug, name, memberCount }`.
- `teamsApi.previewImport(companyId, file)` and `teamsApi.installImport(companyId, body)` — `ui/src/api/teams.ts`. Canonical `api.postForm` + `api.post` calls (correction P-3 — no raw fetch). New `TeamImportPreview` and `TeamImportResolution` interfaces exported alongside. The preview takes a `File`; install takes a JSON body with `yaml` + optional `resolution` and `parentProjectId`.
- `ImportUploadDialog` — `ui/src/components/team/ImportUploadDialog.tsx`. **Replacement for the Slice 2 stub.** Drag/drop zone OR browse button accepts `.yaml` / `.yml` files only, calls `previewImport`, hands the response off to `ImportPreviewDialog` (no separate intermediate state — the second dialog opens directly with the parsed manifest as the initial render).
- `ImportPreviewDialog` — `ui/src/components/team/ImportPreviewDialog.tsx`. Parent department picker (filtered to `type === "department"`, matches the convention in `AddMemberDialog`), per-member collision resolution dropdown (rename / replace / skip — only shown for members with `existingAgentId`), amber warning banner + **disabled Install button** when `skillsToInstall.length > 0` (server would refuse anyway — fail-closed UX). On success: `toast.success`, invalidate `["teams", companyId]` query, navigate to `/team/teams/<slug>`.
- 11 new tests across 2 files. **Server: `team-import-service.test.ts`** — 8 tests: 4 preview (happy path / agent collision detected / malformed YAML throws / already-installed skill filtered) + 4 install (refuse-missing-skills / refuse-multi-lead / refuse-slug-collision / smoke happy path verifying `db.transaction` reaches and returns the right shape). **Server: `team-imports-routes-contract.test.ts`** — 3 contract tests (factory shape + 2 registered POST paths). All shape-only / sequence-mock pattern (`createSequenceDb`); cascade verification in a real DB integration test is deferred to Slice 9 QA — see followups.

All changes additive — existing functionality unaffected. The Slice 2 `ImportUploadDialog` stub is replaced (the file is overwritten, not added), but no other call site depended on the stub's old shape since it was a placeholder.
