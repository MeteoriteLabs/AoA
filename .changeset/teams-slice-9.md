Wire team-export flow + V2-style QA suite (Slice 9 — final slice of the Teams feature):

- `teamExportService.exportYaml(teamId)` — `server/src/services/team-export.ts`. Reads team + members + agents, reconstructs the manifest, serializes via `yaml` package's `stringify`. Throws `notFound` if team doesn't exist. `routing` / `skillDeps` / `pluginDeps` round-trip from the persisted `team.manifest` JSONB blob (so a team that was imported from YAML re-exports with full fidelity, and a team created in the UI exports with the empty/default routing block the scaffolder wrote at create time). Agent-name fallback is `agent-<first-8-chars-of-uuid>` if an agent row was deleted between membership creation and export — the manifest stays well-formed even under referential drift. `version` falls back to `"1.0.0"` for teams created via the UI (no `templateVersion` was ever stored).
- `GET /companies/:companyId/teams/:id/export` route in `teamsRoutes(db)` factory — `server/src/routes/teams.ts`. Sets `Content-Type: application/x-yaml` + `Content-Disposition: attachment; filename="<slug>.team.yaml"` so the browser saves the file natively. Auth is `assertCompanyAccess` only — read-only operation; any company member can export their own team's manifest, no `assertRole("founder","team_lead")` gate required (matches Slice 5/6/7 conventions). Activity log skipped (read-only — symmetric with Paperclip's no-log-on-read pattern).
- Export action in `TeamDetail.tsx` overflow dropdown — `ui/src/pages/team/TeamDetail.tsx`. Replaced the placeholder `MoreHorizontal` icon-button with a working `DropdownMenu` containing "Export as .team.yaml". Click triggers `window.location.href = '/api/companies/${cid}/teams/${tid}/export'` — top-level navigation includes the auth cookie, `Content-Disposition: attachment` makes the browser save the file natively. No JSON-API state, no blob URL plumbing, no CSRF surface beyond what every other GET in the app already has.
- **`teams-qa.test.ts`** — V2-style happy-path sweep covering 5 integration points across the entire Teams feature: (1) `teamsService.create` slug derivation + insert shape, (2) `teamsService.addMember` lead with the dept-membership invariant (Convention C-6 — addMember refuses if the agent isn't already in the parent department), (3) `scaffoldInitial` + `regenerateAutoSections` with user-prose preservation captured via an `update().set()` payload spy (verifies the scaffolder doesn't blow away handwritten coordination prose on regenerate), (4) **headline roundtrip — export team A → import preview to second company → equivalence by name/agents/routing/no-collisions** (the central round-trip test that proves the Teams feature is internally consistent end-to-end), (5) `buildTeamCoordinationSkillEntries` flag-off and flag-on with frontmatter-wrap verification (proves heartbeat injection is opt-in and that the YAML frontmatter correctly maps to `name|description|tools|input_schema`). Test surface mirrors the `v2-integration-qa.test.ts` style — sequence-mock DB pattern, no real drizzle.
- **`team-export-service.test.ts`** — 4 unit tests: happy path with skill list / routing roundtrip from manifest blob / empty team (no members) / `notFound` on missing team. Sequence-mock DB pattern.
