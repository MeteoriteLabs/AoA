Wire `@human` mention notifications at issue comment routes (Slice 7):

- `findMentionedHumans(companyId, body)` exported helper in `server/src/services/issues.ts` — pure resolver that maps `@username` tokens in a comment body to deduplicated human user IDs scoped to the company. Mirrors the existing `findMentionedAgents` pattern with two intentional differences: (1) tighter regex `/\B@([\w-]+)/g` so trailing punctuation like `;`, `:`, `)` doesn't silently break matching; (2) strips a `-h` suffix for disambiguation (`@alice-h` resolves to "alice the human" when both an agent and a human share the name `alice`). JOIN against `userRoles` enforces company scoping. Returns `string[]` deduplicated.
- `notifyMentionedHumans(companyId, body, taskId, actor)` exported orchestrator in `server/src/services/issues.ts` — wraps the full notification flow with all safety layers self-contained. Feature-flag gate via `companies.enableTeams` runs FIRST inside the try block (default `false` means existing companies see zero behavioral change). Outer try/catch guarantees the helper never throws. Sanitized error logging — only `err.name` and `err.message` are logged; never the raw `err` (which would leak stack traces and SQL strings). Per-promise catch on the parallel notification inserts so one failure can't abort the batch. Self-mention skip when `actor.actorType === "user"` matches a mentioned user ID. Notifications are inserted via the existing `notificationService.create()` with `relatedEntityType: "task"` and `relatedEntityId: taskId` so the sidebar deep-links navigate to the task page (where the comment is rendered inline).
- Both `findMentionedAgents` call sites in `server/src/routes/issues.ts` (line ~676 in the UPDATE-with-comment handler, line ~1050 in the POST-comment handler) now call `svc.notifyMentionedHumans(...)` immediately after the existing wakeup loop. Single line at each site — ~25 lines of duplicated route-side try/catch removed since the safety layers all live in the service helper now. The new code lives inside the existing `void (async () => {})()` IIFE that follows the comment save, so even unhandled errors can never break the route response.
- **Adapter compatibility**: zero adapter changes. Notification rows surface via the existing `GET /companies/:cid/notifications` and `GET /unread-count` endpoints (already wired into the sidebar's unread badge in the UI).
- 18 new tests across 2 files: `server/src/__tests__/mention-resolver-humans.test.ts` (9 tests for the resolver — happy path, no mentions, `-h` suffix disambiguation, agent-name filtering, trailing punctuation, case-insensitive matching, user-row dedup, token dedup, and a regression test for trailing punct) + `server/src/__tests__/mention-resolver-humans-coverage.test.ts` (9 tests — 6 static-analysis pins that BOTH route call sites have the safety contract wired, plus 3 behavioral: feature-flag-off short-circuit, self-mention skip, multi-mention parallel insert).

Risk mitigations: feature flag default `false` so existing companies see zero behavioral change; failure isolation in three layers (outer try/catch in the helper, per-promise catch on the parallel batch, IIFE wrapper at the route that already isolates async failure from the route response); sanitized error logging drops stack traces and SQL strings; comment creation always succeeds even if notification fails (append-only); pre-existing `findMentionedAgents` logic UNCHANGED — only the route-side dedup changed (from inline try/catch to a single helper call).
