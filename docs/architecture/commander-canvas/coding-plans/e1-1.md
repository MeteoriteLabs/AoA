# E1.1 — Shared controller implementation addendum

**Status:** Review candidate; existing isolated implementation is excluded. **Version:** V1. **Spec:** [slice](../slice-plans/e1-1.md), [reference controller](e1-1-canvas-controller.md), U04–U05. **Architecture:** one controlled panel registry; React Flow renders it. **Stack:** React, TypeScript, candidate React Flow, Vitest and Playwright. Reference code is proposed design, not approval of the premature code.

## E1.1/1 — Registry and lifecycle

- [ ] Create `ui/src/components/universe/panel-state.ts` from the reviewed reference types/reducer, not from the unapproved worktree. Add `panelKey`, `initialState`, `panelReducer`, `displayRect`, `openingRect`; keep their complete signatures and state transitions in the linked reference plan.
- [ ] Add reference test cases to `ui/src/components/universe/__tests__/panel-state.test.ts` under Vitest. Cover repeated entry, different artifact versions, close/reopen generation, cross-company rejection, invalid geometry, human movement of pinned panels, rejected Commander arrangement and maximize/minimize/restore cycles. Every reference assertion is a planned regression case, not proof of rendering.
- [ ] Make the registry the only owner of geometry/order/minimized/maximized state. Commit state immediately on action; a transitionend callback must never decide whether minimize or close occurred. Selected key must be null or refer to a visible existing panel.
- [ ] Add bounded undo/redo history of human/authorized Commander geometry operations in `panel-history.ts`: previous/next normal rect + panel generation, maximum 50 entries (initial engineering bound). Ignore records for closed/reopened generations; content edits and domain writes never enter layout undo.

## E1.1/2 — Pointer and focus handling

- [ ] Implement `PanelFrame.tsx` as the shared header/body shell and `PanelNode.tsx` as the React Flow adapter. The reference plan's inline PanelNode must be split at this boundary so task content cannot own a competing shell. Give the root `role="region"`, `aria-label={title}` and diagnostic key/generation attributes.
- [ ] Map all eight resize edges/corners and header-only drag through the controlled adapter described in the reference plan. Text/body scroll and buttons use `nodrag nopan nowheel`; route events by key/generation, never DOM title lookup.
- [ ] Keep minimized content mounted but inert/hidden until its renderer explicitly supports suspend/restore. On minimize/close restore focus to the calling tray/overview control. Maximize projects the usable viewport without replacing normal rect; disable camera pan while maximized.
- [ ] Implement gesture shields for embedded content and release them on pointerup/cancel, blur, scope change and unmount. Test drag across iframe boundaries and rapid close during resize. Keyboard move/resize and focus ring are independent of selected-header tint.

## E1.1/3 — Renderer adaptation

- [ ] Create `UniverseWorkspace.tsx` with one controller provider keyed by company/user/conversation. Register node types outside render and use the exact controlled mapping in the reference plan. Remove built-in graph connection/delete shortcuts; no graph edges appear.
- [ ] Inject authorized content by stable reference. Missing renderer displays loading/unavailable inside the operable frame; failed render is caught by a body error boundary. Body suspension cannot stop canonical jobs.
- [ ] E2.4 supplies real TaskConversationPanel. E4/E6 supply artifact/browser renderers. Until those bind, fixture frame tests close only generic geometry acceptance, not actual content-route integration.
- [ ] Qualify the candidate React Flow version and runtime exports in the authorized implementation environment before install. Manifests and regenerated lockfile must travel together. The earlier installed version is evidence to investigate, not an inherited dependency decision.

## Verification and limits

Use the exact unit/frame/workspace/E2E commands in the reference plan. Add `panel-history.test.ts` with undo after close/reopen, undo of pinned human move and refusal to replay old generation. Browser journeys must exercise 0.5/1/2 camera zoom, unmeasured viewport and narrow bounds, including all entry points from E1.0/E2.4.

Bounds and timings in the reference module are initial engineering choices, not measured performance guarantees. Performance qualification records frame/pointer latency at 1, 10 and 50 panels; above the measured rendering budget suspend hidden expensive content, preserving canonical registry/drafts. Reject excessive persisted counts via E1.2 instead of silently discarding panels.

Rollback disables Universe mounting; it does not remove tasks/artifacts or rewrite saved data. Re-review source compatibility before implementation. No code or dependency changes occur while producing this plan.
