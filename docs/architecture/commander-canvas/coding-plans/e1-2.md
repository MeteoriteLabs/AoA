## Contract

Proposed exported service `universeStateService(db)` has `get(scope)`, `apply(scope, patch)` and `getReceipt(scope, operationId)`. `scope={companyId,userId,conversationId}` is derived from authenticated request and canonical conversation ownership, not body-supplied actor fields. V1 personal layout writes are owner-only even when another user can read a shared conversation. Register GET/PATCH `/api/companies/:companyId/universe/conversations/:conversationId/layout` and GET `.../layout/operations/:operationId`. Missing/inaccessible conversation returns the existing not-found convention; invalid operation 400, stale revision or reused ID/content mismatch 409.

```ts
export type LayoutOp =
  | { type:'open'; key:string; ref:{kind:string;id:string;version?:string}; rect:Rect }
  | { type:'geometry'; key:string; rect:Rect }
  | { type:'pin'; key:string; value:boolean }
  | { type:'minimize'; key:string; value:boolean }
  | { type:'close'; key:string }
  | { type:'order'; keys:string[] }
  | { type:'viewport'; x:number; y:number; zoom:number };
export type Rect = {x:number;y:number;width:number;height:number};
export type LayoutPatch = {schemaVersion:1;operationId:string;expectedRevision:number;operations:LayoutOp[]};
export type LayoutAck = {operationId:string;revision:number;schemaVersion:1};
```

Use a strict discriminated Zod union; `kind` must be the accepted reference-kind enum, not arbitrary render code. Ref authorization is checked before inclusion/preview; no content bodies, credentials, raw audio, cookies or live control tokens in layout. Proposed initial transport bounds: 200 records, 50 operations/patch, 64 KiB patch, 256 KiB snapshot, finite coordinates within ±1,000,000 and dimensions 1–8192 canvas units. Zoom 0.25–2 follows the reference controller; bounds require host qualification, not capacity claims.

## E1.2/1 — Persistence transaction

- [ ] Define `universe_layouts`: UUID id, companyId, userId, conversationId, schemaVersion=1, revision bigint=0, JSON document and timestamps; unique owner/company/conversation. Define `universe_layout_operations`: layoutId/companyId, operationId, canonical payload hash, acknowledged revision and timestamp; unique(layoutId,operationId). Export both, generate migration and check FK/cascade behavior on a disposable migrated database. Every service query carries companyId and authenticated userId; receipts are reached through their authorized parent layout. Never use an operation UUID as standalone authorization.
- [ ] Authenticate/access-check before receipt reads. In one company/owner-scoped Drizzle transaction ensure owner row exists (`onConflictDoNothing`), lock/read it, then look up receipt before checking expectedRevision. Equal receipt/hash returns original ack; different hash conflicts. Otherwise require matching revision, authorize refs, apply validated operations, update revision and insert receipt atomically. A failed transaction produces neither receipt nor partial geometry.
- [ ] Use existing `insertActivityLog(tx,input)` from `server/src/services/activity-log.ts` in the transaction for a successful new operation, then `publishActivityLogged(persisted)` after commit. Receipt replay does not create repeated domain work. Never log text/artifact contents. Publication failure cannot undo the committed operation or justify replaying it.
- [ ] Add real DB tests in `server/src/__tests__/universe-state.integration.test.ts`, using the migrated PostgreSQL setup and `insertTestCompany` pattern from `home-board-layout.integration.test.ts`. Seed two companies, two users, two conversations; concurrent revision-zero writes must yield one ack and one conflict. Assert cross-owner and cross-company route/service reads and writes fail. Any referenced distributed job is read separately through the existing non-owner tenant transaction; its RLS tests remain distinct from UI-state ownership tests.

Representative service-test body, inside that real seeded fixture (the fixture supplies `svc`, authorized `scope` and seeded task key `key`):

```ts
const patch = {schemaVersion:1 as const, operationId:crypto.randomUUID(), expectedRevision:0,
  operations:[{type:'pin' as const,key,value:true}]};
const a = await svc.apply(scope, patch);
expect(await svc.apply(scope, patch)).toEqual(a);
await expect(svc.apply(scope,{...patch,operations:[{type:'pin',key,value:false}]}))
  .rejects.toMatchObject({status:409});
expect((await svc.get(scope)).revision).toBe(1);
```

Seed the referenced panel before setting the revision-zero fixture snapshot; a missing key is a validation failure, not silent creation. Test nonexistent keys, duplicate order keys, unknown schema, oversized payload and nonfinite geometry explicitly.

## E1.2/2 — Conflict and reload recovery

- [ ] `useUniverseState` retains acknowledged snapshot separately from optimistic operations. Debounce transient geometry (proposed 250 ms), flush final gesture immediately, and show saving/saved/offline/conflict based on server acknowledgement, never local animation.
- [ ] On lost ack query the operation receipt first. If absent, fetch snapshot. Rebase only property changes whose base property is unchanged; same-property edits preserve local candidate and require explicit resolution. Resubmission uses a new operationId only after resolving the old operation's outcome and recomputing expectedRevision.
- [ ] Keep receipts for the life of the layout initially; do not add arbitrary TTL that permits old IDs to apply twice. Later retention needs tombstone/expiry semantics and measured storage review. Bound the client pending journal (100 patches/1 MiB proposed); on overflow stop enqueueing and preserve a downloadable/recoverable local snapshot rather than falsely showing saved.
- [ ] Reload fetches authorized snapshot before rendering cached previews. A smaller viewport computes display clamps without persisting them as preferred geometry. Logout/company switch cancels in-flight requests and clears accessible cached data; offline local retention follows explicit policy, not an assumed secure browser store.
- [ ] Test two tabs changing independent properties, same-property conflict, lost-ack receipt, scope switch before reply, snapshot version mismatch and reload during save in `tests/e2e/universe-persistence.spec.ts`.
