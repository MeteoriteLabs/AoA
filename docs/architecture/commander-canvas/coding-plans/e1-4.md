**Status:** Review candidate; UI tests unrun. **Version:** V1. **Spec:** [slice](../slice-plans/e1-4.md), U02–U03, E1.1 registry, E8.1 preferences. **Architecture:** one popup owner and one panel registry projection; previews are passive view models. **Stack:** React, existing UI primitives, Vitest/Testing Library/Playwright.

## Files and contract

Create `ui/src/components/universe/UniverseTray.tsx`, `OpenPanelOverview.tsx`, `PanelPreview.tsx`, `tray-state.ts`; consume existing domain clients through authorized reference adapters. Modify only Universe composition and query-key registration, not HubShell's existing tab behavior. Tests: `__tests__/tray-state.test.ts`, `__tests__/UniverseTray.test.tsx`, `tests/e2e/universe-navigation.spec.ts`.

```ts
export type TrayMenu='commander'|'work'|'artifacts'|'inbox'|'browser'|'settings'|'open-panels';
export type TrayState={expanded:boolean;menu:TrayMenu|null;manualCollapse:boolean};
export type TrayAction={type:'logo'}|{type:'menu';menu:TrayMenu}|{type:'dismiss'}|{type:'reenter'};
export function trayReducer(s:TrayState,a:TrayAction):TrayState {
  if(a.type==='logo') return {expanded:!s.expanded,menu:null,manualCollapse:s.expanded};
  if(a.type==='menu') return {expanded:true,menu:s.menu===a.menu?null:a.menu,manualCollapse:false};
  if(a.type==='dismiss') return {...s,menu:null};
  return {...s,manualCollapse:false};
}
```

Auto-hide reveal occurs only when configured, no menu is active and manualCollapse has been cleared by a genuine pointer exit/re-entry or deliberate activation. Keyboard focus/tap provides equivalent access. One stationary logo DOM element retains hit-area/size; equal-width wings animate around it without moving its center.

## E1.4/1 — Icon tray and menus

- [ ] Implement the reducer above and test opening Work then Inbox yields only Inbox; logo closes current menu; Escape/outside click dismisses one menu; manual collapse does not immediately reopen under the same pointer.
- [ ] Use accepted icon entries and separate Commander primary toggle from its adjacent menu. Accessible primary name is `Commander`; adjacent menu trigger is `Commander options`. Primary restores hidden chat, focuses covered chat, tucks frontmost chat; never changes voice/blob/captions. The options menu exposes independently labelled `Chat`, `Blob`, `Captions` checkbox items and authorized recent/new conversations. Tests must activate the options trigger to access these items, not assume the primary icon opens a menu.
- [ ] Each menu uses a shared focus-managed popup primitive and a search field within its own scope. Only nonzero counts render badges. Selection resolves an authorized reference then dispatches one `open` action by key/generation. Do not embed live panel controls in a thumbnail.
- [ ] Consume `dockHiding` from E8.1; always-visible remains expanded by default with manual collapse available. Save persistent preferences separately from transient open menu. Scope change dismisses menus and drops cached other-company previews before new data appears.

## E1.4/2 — Open overview, rails and restoration

- [ ] Derive Open panels from the current conversation's registry, including open/focused/minimized views. Close removes an item, minimize retains it. Library items appear only in their library menu. Persist an immutable `openedOrdinal` on creation and sort overview tiles by it; the controller's z-order list changes on focus and must not supply overview order. Allocate the next ordinal atomically with the layout open operation; reopening a closed instance gets a new ordinal, minimizing/restoring retains it.
- [ ] Render responsive readable tiles and explicit Previous/Next page controls rather than horizontal scrolling. Proposed tile minimum 220×140 CSS px; calculate columns from usable popup width and rows from available height, at least one tile/page. Count and page count are derived, no shrinking to illegible cards.
- [ ] Left rail projects only minimized/out-of-view open panels; right rail consumes E7.3 attention. E8.1 Auto/Always/Hidden changes affordances, not canonical item state. Hidden rails remain recoverable through tray/Inbox.
- [ ] Hover/focus preview uses a short intent delay (proposed 180 ms) and continuous trigger-to-preview hit region; pointer leave delays dismissal (120 ms) and cancels it on preview entry. Tap opens preview, explicit selection opens content. Reduced motion has no fly-in. Capture only authorized preview data, never clone DOM IDs, event handlers, form inputs or third-party browser pixels without the owning host's supported capture path.
- [ ] Selecting a tile restores/focuses its existing instance, then E1.6 brings it into view. Multiple launch paths for the same reference must resolve one panel. Navigation to deleted/revoked content renders unavailable and removes sensitive preview text after reconciliation.

## Verification and rollback

Testing Library asserts accessible menu ownership, badge absence at zero and keyboard return focus. Playwright covers 0/1/30/200 registry records, pagination at three viewport sizes, fast switching, lost hover, minimized restore and scope switch. 200 is the proposed persistence bound, not a measured running-browser capacity. Verify no page has horizontal scrolling caused by overview. Feature-disable restores ordinary app navigation; no canonical task/artifact is changed by removing the tray.
