# E1.3 — Destination draft and submission recovery implementation plan

**Status:** Review candidate; runtime unrun. **Version:** V1. **Spec:** [slice](../slice-plans/e1-3.md), [state](../state-contract.md), U06–U07. **Architecture:** separate owner/destination drafts; canonical message services own submission. **Stack:** Drizzle, React Query, existing Commander and task API clients.

The source-specific answer adapters and E5 pending-action metadata contract are defined in [shared bindings](../implementation-bindings.md#draft-destination-adapters). The text Draft example below is for Commander/task messages; answer fields use their source schema, never this text shape or a generic submit endpoint.

## Files and interfaces

Extend `packages/db/src/schema/universe.ts` with `universe_drafts`; create `server/src/services/universe-drafts.ts`, `ui/src/components/universe/useUniverseDraft.ts` and `draft-state.ts`; extend `server/src/routes/universe.ts`, `ui/src/api/universe.ts` and shared validators. Tests: `server/src/__tests__/universe-drafts.integration.test.ts`, `ui/src/components/universe/__tests__/draft-state.test.ts`, `tests/e2e/universe-drafts.spec.ts`.

Pinned existing `CommanderInput` and `InternalAgentPanel` manage input references; reuse their attachment validation and canonical clients. `issuesApi.addComment` and `addCommentWithAttachments` already accept clientSubmissionId. Commander chat accepts message max 10,000 chars and five attachment asset IDs; draft validation must honor the destination's existing validator, not broaden it.

```ts
export type Destination = {kind:'commander'|'task'|'question'|'runtime_decision'|'approval';id:string};
export type Draft = {revision:number;text:string;attachmentAssetIds:string[]};
export type SentSnapshot = Draft & {clientSubmissionId:string};
export function afterAcknowledgement(current:Draft, sent:SentSnapshot):Draft {
  const unchanged = current.revision===sent.revision && current.text===sent.text &&
    JSON.stringify(current.attachmentAssetIds)===JSON.stringify(sent.attachmentAssetIds);
  return unchanged ? {...current,text:'',attachmentAssetIds:[]} : current;
}
```

This proposed pure function changes local fields only; the server draft clear is a separate CAS patch after durable ack. Scope key is company/user/conversation/destination-kind/destination-id, never panel index or display title. `useUniverseDraft(scope,destination)` exposes `{draft,status,error,patch,submitSnapshot,acknowledge}`; `submitSnapshot` allocates and returns the immutable sent snapshot but does not execute a request by itself.

## E1.3/1 — Draft storage

- [ ] Add unique scoped destination row with revision, text, attachment references and updatedAt; add its tenant registration/exports and generated migration. Use GET/PATCH `/api/companies/:companyId/universe/conversations/:conversationId/drafts/:destinationKind/:destinationId`; validate conversation and task membership/permission separately. No client userId field is accepted.
- [ ] Persist edits with expectedRevision and bounded text/attachments. On revision conflict retain both versions; do not concatenate automatically. Draft text may be private even when its task is shared. Foreign destination IDs must not reveal existence.
- [ ] Reuse validated asset references from composer upload; unresolved/failed attachments remain visible pending items and cannot silently attach to a different task. Cancel upload on destination/account switch or retain it under its originating draft key.
- [ ] Keep geometry out of draft rows. Close, minimize and maximize cannot clear a draft. Reset appearance/layout cannot delete draft data. Local offline caching is separately policy-gated; default durable store is the authenticated service, not unscoped localStorage.
- [ ] Test all pairs of company/user/conversation/destination for isolation using real DB fixtures; concurrent revisions, deleted task, revoked asset and failed-save recovery. Use the migrated Postgres harness from E1.2 and explicit auth middleware integration, not only service mocks.

## E1.3/2 — Submission acknowledgement and uncertain outcome

- [ ] On Send freeze text, refs and destination, allocate clientSubmissionId once, and call the existing destination client. Later selection changes cannot retarget this submission. Prevent duplicate local presses while the same snapshot is pending; still rely on canonical server idempotency.
- [ ] Clear only the sent snapshot after durable acknowledgement. If the user typed more while sending, retain the newer draft. Add these concrete pure tests:

```ts
it('keeps text typed after Send', () => {
  const sent={revision:4,text:'first',attachmentAssetIds:[],clientSubmissionId:'s1'};
  const current={revision:5,text:'second',attachmentAssetIds:[]};
  expect(afterAcknowledgement(current,sent)).toEqual(current);
});
it('clears exactly the acknowledged snapshot', () => {
  const sent={revision:4,text:'first',attachmentAssetIds:[],clientSubmissionId:'s1'};
  expect(afterAcknowledgement(sent,sent).text).toBe('');
});
```

- [ ] On timeout/reload, mark pending outcome and use E2.2 Commander lookup or the existing task comment idempotency identity/read path. Do not post again on reconnect. If task lookup cannot conclusively identify the submission, retain unknown and expose deliberate retry only after explaining possible prior acceptance; add a read-only task outcome binding before calling automatic recovery complete.
- [ ] E2.4 maps reply controls to task destinations and E1.5 maps compact/expanded chat to one Commander draft. Verify switching between two task composers during pending sends keeps each reply in its original thread.

## Acceptance and rollback

Run draft-state unit cases, real DB auth/CAS tests and reload/lost-ack E2E. No automatic job starts from typing, upload or restoring a draft. Feature-disable stops new edits through Universe while canonical reply APIs remain intact; preserve draft rows. User-initiated discard is explicit and destination-scoped. Server-side draft retention policy must be recorded before release; no arbitrary deletion job is introduced by this slice.
