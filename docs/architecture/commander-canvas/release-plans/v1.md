# Universe V1 — release plan

**Status:** Scope allocation accepted; implementation methodology and technical readiness remain pending. Includes 30 existing slices; excludes only E3.4 from the current 31-slice register. See the [acceptance record and epic allocation](README.md) and [individual plans](../slice-plans/README.md).

## Product outcome

A persistent, themeable spatial Universe with a stable icon tray; trustworthy movable/resizable panels; independent Commander chat/blob/captions; real realtime voice; governed browser automation and local/cloud viewing and takeover; canonical artifacts and tools; task conversations, routines and consistent attention.

The reviewed UI, motion, accessibility, settings and recovery behaviors are acceptance requirements, including those lost in mock rebuilds. The mock's intermittent task route remains an explicit design/verification gap.

Milestones overlap only where their dependency contracts permit. A slice appearing in multiple checkpoint rows is delivered in increments, counted once; completion requires all its increments. E8.1 travels with consumers. No milestone alone is permission to ship a reduced V1.

## External dependency handling

Use the [fresh readiness register](../readiness-review.md): BASE, DESIGN, CMD, BROWSER, CLOUD, PROFILE, APPROVAL, VOICE and HOST. Owners and closure evidence remain explicit. Shared replatform fixes belong upstream; Universe supplies consumer acceptance. No copied authority or weaker transport guard may bypass a gate.

A gate blocks affected increments, not unrelated V1 work. If no independent V1 work remains, report the blocking dependency and owner; do not begin V2. Signed-out browser qualification cannot close saved-profile acceptance. One successful voice provider cannot close the other two.

## Exit criteria

- [ ] Every included slice and its increments has verified evidence, not only an approved plan.
- [ ] Actual provider/worker capability results and applicable upstream program gates are accepted at the integrated revision.
- [ ] UI state gaps, task entry routes, all panel lifecycle operations, keyboard/touch and reduced-motion journeys pass in supported hosts/viewports.
- [ ] Draft/geometry conflicts, uncertain submissions, context recovery, duplicate/missed events, revoked access and browser controller changes are covered.
- [ ] All retained settings have correct ownership, defaults, persistence, failed-save behavior and reset semantics; budgets remain in Budget & caps.
- [ ] Capacity, sustained-session/resource and format limits are measured and disclosed without claiming unsupported parity.
- [ ] Repository typecheck, full tests and build pass; migration and feature rollback preserve canonical records.
- [ ] Commercial rollout prerequisites are resolved before enabling a paid managed offering; technical support does not imply a billing commitment.
- [ ] Product review records V1 acceptance. Only then may V2 implementation start.

## Branch sequencing

Accept a verified replatform base before creating the Universe integration branch. Reviewable increments integrate there; bring upstream changes in regularly and re-run impacted checks. After replatform lands, reconcile the actual main ancestry, accounting for squash or preserved commits, then verify the combined tree. This document creates no branch and assumes no merge has happened.
