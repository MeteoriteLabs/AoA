## Proposed disposition

Move full E8 after the first milestone. Preserve all implemented browser control-plane slices and findings as the starting point for a later browser milestone.

## Present evidence

The epic remains `backlog`. Browser job/session, approval, host-spawn guard, and related control-plane plumbing have implemented slices, but the current records state that no complete sandbox-local browser executor and no D3 completion campaign exist.

## Record integrity

Slice evidence may be retained only for the mechanisms it exercises. No partial browser plumbing or inert policy object may be read as an E8 pass.

## Retained scope

## Deferred scope

All E8 completion scope is deferred from the coding milestone. It is not deleted and remains required before any program claim that includes browser capability or the broader private beta.

## Remaining implementation

## Grooming actions

Reconcile implemented slices against the original browser tickets, assign successors for noncanonical results, and write a later-milestone plan that makes provider/network limitations explicit.

## Candidate QA

The later candidate must run D3 on real infrastructure with browser execution, metadata/private/control-plane probes, redirects/DNS rebinding, credential rotation, approvals, reconnect, artifacts, cancellation, and cleanup.

## Completion handoff

Require a fresh E8 `Result: pass` record and a same-candidate completion handoff. No first-milestone handoff is proposed.

## Dependencies / reopen triggers

Depends on completed E7 capability and its current E3–E6 inputs. Reopen retained slices for runtime/provider/policy changes or when the later browser milestone is approved.

## Gate-review readiness

**Can enter gate review now? No.** The executor and D3 campaign are not complete, and E8 is intentionally after the first milestone.
