## E1-F001 — PRT-002 Step-2 illustrative transition maps diverge from the E0 lifecycle JSON authority

- **Severity:** Medium (would produce an incorrect state machine if transcribed literally).
- **Blocks gate:** No.
- **Blocks execution until amended:** Yes (execution paused for a plan amendment per operator directive; PRT-002 must not be implemented from the divergent examples).
- **Discovered during:** E1 controller read-back / pre-implementation cross-check (before PRT-001).
- **Evidence:** The canonical lifecycle authority is `docs/architecture/distributed-execution-lifecycles.json` (Decision #121; frozen E0/FND-001 output). The E1 `implementation-plan.md` PRT-002 Step 2 (Task 2) embeds *illustrative* expected transition maps that omit real edges present in that JSON and, in one case, assert a phantom edge the JSON does not contain:
  - **attempt:** plan omits `pending→expired`, `leased→cancelled`, `cancel_requested→succeeded`; plan asserts `offered→cancel_requested`, which the JSON does **not** have (JSON has `offered→cancelled`).
  - **browser_session:** plan omits `queued→expired`, `leased→cancelled`, `starting→cancelled`, `active→cancelled`, `waiting_approval→cancelled`, `cancel_requested→succeeded`.
  - **service_instance:** plan asserts `pending→stopped` (a phantom; JSON has `pending→lost`) and omits `leased→failed`.
  - `job`, `lease`, and `service_desired` illustrative maps already match the JSON.
- **Affected tickets:** PRT-002 (result ledger + tests + `states.ts`).
- **Root cause / resolution:** The plan's own **normative** hardening amendment ("PRT-002 — separate lifecycle machines") already states the E0 JSON is authoritative — "Generate transition constants/predicates from the E0 JSON authority **or** validate byte-for-byte semantic parity with it," and "The E0 JSON owns these edge conditions." The Step-2 examples are non-normative and stale. Proposed disposition: amend PRT-002 Step 2 to (a) correct the attempt/browser/service-instance illustrative maps to the exact JSON edges and (b) require a parity test that loads `distributed-execution-lifecycles.json` and asserts the embedded `states.ts` maps/guards/terminals equal the JSON's `allowed`/`guards`/`terminal` sets exactly (the same authority-cross-check pattern PRT-004 uses for the shared canonicalizer). Runtime `states.ts` embeds literal maps (no `fs`); the `.test.ts` performs the parity load. **Resolved: decision [E1-D001](decisions.md) locked and PRT-002 Step 2 amended (2026-08-09) by the operator acting as custodian / Integration Gate Owner.**

## E1-F002 — PRT-006 golden-journey parity is vocabulary/enum membership, not full-object schema parse; `emits` vocabulary is broader than the worker-event union

- **Severity:** Medium (literal implementation of two Step-6 bullets would fail against the frozen fixtures).
- **Blocks gate:** No.
- **Blocks execution until amended:** Yes (PRT-006 `golden-journeys.test.ts` design).
- **Discovered during:** E1 controller read-back / pre-implementation cross-check (before PRT-001).
- **Evidence:** The frozen FND-004 golden-journey fixtures (`tests/fixtures/distributed-execution/*.json`, immutable E0 output validated by `schema-v1.json`) use identity encodings and an emission vocabulary that differ from the E1 wire schemas:
  1. **`emits` vocabulary:** `steps[].emits` in the fixtures contains 4 names outside PRT-004's worker-event union — `artifact_transfer_rejected`, `quarantine_grant_issued`, `quarantine_receipt_finalized`, `replacement_lease_activated` (artifact/quarantine/lease **operation** concepts owned by PRT-003/005/007, not worker events). `expectedEvents[].eventType` additionally uses `budget_exhausted`, `lease_lost`, `cancel_requested`, `producer_safety_rejected`, `provider_pause_observed` — control-plane journey events, not worker→control-plane wire events. The plan's Step-7 note ("golden journeys pass once event-name mapping includes `network_denied`") understates this.
  2. **`source` shape/encoding:** the fixture `Source` is `{ kind, runId?, issueId? }` with ULID-style IDs (`run_…`, `issue_…`) and no `requestedBy`/`executionPrincipal`; it therefore **cannot** parse through the full `executionSourceV1Schema` (UUID-branded IDs + mandatory typed principals). Likewise fixture events use `^[0-9A-HJKMNP-TV-Z]{26}$` IDs and an integer `fenceToken`, versus the E1 UUID/base64url wire encoding.
- **Affected tickets:** PRT-006 (`golden-journeys.test.ts`). (PRT-004's digest cross-check is unaffected: it canonicalizes the raw fixture event objects and reproduces the committed `eventDigest` regardless of E1 wire schema.)
- **Root cause / resolution:** The fixtures are immutable frozen E0 authority, so the PRT-006 test must conform to them. The two Step-6 bullets ("source parses through `executionSourceV1Schema`…" and "every `emits` value parses as a known worker event type") should be reframed as **vocabulary/enum-membership parity**, not full-object schema parse: assert fixture `source.kind` ∈ the `ExecutionSourceV1` discriminant set, and assert each `emits` value ∈ a reviewed "known distributed-execution emission vocabulary" = the worker-event type union ∪ the frozen non-event operation/receipt names above. **Resolved: decision [E1-D002](decisions.md) locked and PRT-006 Step 6 amended (2026-08-09) by the operator acting as custodian / Integration Gate Owner.**

## E1-F004 — PRT-003 local extension byte-sizer diverges from the E0 RFC-8785 canonical authority: `jobEnvelopeV1Schema` fails OPEN on non-canonicalizable extension values (floats, unsafe integers, lone surrogates)

- **Severity:** High (fail-open at a `.strict()` security-critical wire envelope; admits values the program's canonical/event pipeline cannot process).
- **Blocks gate:** No (epic gate). **Blocks PRT-003 approval:** Yes (reviewer disposition `changes_requested`).
- **Discovered during:** PRT-003 independent review (reviewed revision `d381a3a46f16f5ef05c26a0b8101be63509f927a`).
- **Context:** PRT-003 must bound each extension value at "≤16,384 **RFC-8785-canonical** UTF-8 bytes" (plan hardening amendment, [implementation-plan.md](implementation-plan.md) line 71). Because the shared `canonical-json.ts` is a PRT-004 deliverable, `job.ts` carries a small **self-contained** canonical serializer (`canonicalString`/`canonicalJson`/`canonicalByteLength`, lines ~161–196) used only to size extension values (the implementer's own Concern #1 / Deviation 1). The program pins "RFC-8785 canonical JSON" to the **frozen E0 implementation** `scripts/check-distributed-execution-foundation.mjs` (`canonicalizeJson`), and the amendment's PRT-004 clause (line 97) **explicitly enumerates** "lone surrogates, unsafe-integer boundary … `-0`" as the exact edge cases where the two canonicalizers must **not** diverge.
- **Evidence (independently reproduced against the reviewed revision):**
  - **In-subset agreement is perfect** — a 23-case battery (nested objects/arrays, multibyte `é`/astral emoji, combining NFD, every control-char escape, integers, `-0`, booleans, `null`, key-ordering variations, unicode keys) produced **byte-for-byte identical** canonical strings and byte counts to E0; the real-schema value byte-budget boundary matches E0's count exactly at 16,384 pass / 16,385 fail for ASCII **and** multibyte (`é`). So the sizer is correct for representable values.
  - **Out-of-subset DIVERGES on accept/reject.** E0 `canonicalizeJson` **rejects** floats ("float is not allowed"), unsafe integers ("unsafe integer is not allowed"), and lone/broken surrogates ("lone … surrogate in string"). The local `canonicalJson` **silently accepts** all of them (numbers via `String(value)` with only a `Number.isFinite` guard; strings emit surrogate code units verbatim, and `TextEncoder` then substitutes U+FFFD). The structure walk `addExtensionValueStructureIssues` only flags non-**finite** numbers, so floats, unsafe integers, and lone-surrogate strings pass unflagged.
  - **The divergence reaches the REAL `jobEnvelopeV1Schema`.** `jobEnvelopeV1Schema.safeParse(job)` **returns `success: true`** for a job whose extension value is `1.5`, `9007199254740992` (2⁵³), a lone-surrogate string `"\uD800"`, `{ rate: 0.25 }`, or `[9007199254740992]` — every one of which E0 declares non-canonicalizable. It also **propagates through `leaseOfferV1Schema`** (a lease offer whose nested job carries a float extension value is accepted).
  - **Concrete miscount for unsafe integers:** the local sizer serializes input `9007199254740995` as `"9007199254740996"` (double-precision rounding), so the "canonical bytes" it charges against the budget do not even correspond to the supplied integer.
- **Impact:** (1) A `.strict()` security-critical envelope fails **open**, admitting extension values that have **no** RFC-8785-subset canonical form. (2) The "≤16,384 RFC-8785-canonical bytes" invariant is meaningless for such values (phantom / miscounted size), a budget-bypass surface. (3) Downstream break: the same job, once embedded in an event and digested via the authoritative E0/PRT-004 canonicalizer (`eventDigest = SHA-256 of RFC-8785 canonical JSON`, amendment line 95), will **throw** — a job PRT-003 declared valid cannot traverse the event pipeline. This is exactly the silent two-canonicalizer divergence the program's cross-implementation cross-check (line 97) exists to prevent, and the implementer's self-report claim that "the byte semantics already match the amendment" holds only for in-subset values.
- **Affected tickets:** PRT-003 (fix now); PRT-004 (the shared `canonical-json.ts` unification is the eventual convergence, and its cross-implementation digest cross-check would surface any residual gap).
- **Root cause / resolution:** The local sizer is a third canonicalizer whose accept/reject boundary was never aligned with the frozen E0 authority. **Required fix (within PRT-003 scope, no PRT-004 pre-emption):** make an extension value that is not canonicalizable under the frozen RFC-8785 subset **fail closed** — reject non-integer numbers, non-safe integers, and lone/broken surrogate strings, matching E0's `canonicalizeNumber`/`canonicalizeString` reject behavior (making the local `canonicalJson`/`canonicalString` throw on those is minimal, since `addExtensionArrayIssues` already converts a canonicalizer throw into a "not canonicalizable" issue; ideally also flag the offending path in `addExtensionValueStructureIssues`). Add tests asserting float / unsafe-integer / lone-surrogate extension values are rejected.
- **Status: RESOLVED (resolving revision `e62921b1743f9cbc33e6ecf79348a7f4bf5d5483`).** `job.ts` `canonicalString` now throws on a lone high surrogate (not followed by a low) and on a stray low surrogate; `canonicalJson` throws on `!Number.isInteger` (float) and `!Number.isSafeInteger` — byte-for-byte with the E0 authority's `canonicalizeString`/`canonicalizeNumber`, and the existing `addExtensionArrayIssues` try/catch turns the throw into a fail-closed "not canonicalizable" `custom` issue at the extension value path. Independently re-verified at PRT-003 review **attempt 2 (`approved`)**: `1.5`, `9007199254740992`, `"\uD800"`, `"\uDC00"`, `{rate:0.25}`, `[9007199254740992]` now return `success:false` on BOTH `jobEnvelopeV1Schema` and `leaseOfferV1Schema` (nested-job + own-extensions, issue path at the extension value); in-subset values still pass with 23/23 byte-for-byte E0 agreement and the value-budget boundary unchanged (16,384/16,385); valid astral emoji pairs are not falsely rejected. Diff scoped to `job.ts` (+26) + `job.test.ts` (+13 assertions) + ledger; focused 93/93, full 124/124, typecheck/build/boundary all exit 0.
- **Non-blocking follow-up (PRT-004):** the local `job.ts` extension byte-sizer remains a second canonicalizer that duplicates the E0 semantics. When PRT-004 introduces the shared, zero-node-import `canonical-json.ts`, unify `job.ts` onto it so the package carries a **single** canonicalizer (single source of truth), and let PRT-004's cross-implementation digest cross-check guard any residual drift. Not required for PRT-003 (the reject-direction parity is now proven), tracked to PRT-004.

## E1-F003 — PRT-002 `index.ts` uses `export *`, defeating the package's explicit-public-exports review convention

- **Severity:** Medium (review integrity). The functional wire surface is currently correct — I verified `export *` re-exports exactly the intended 48 identifiers and leaks no transition-map/guard/private helper — so this does **not** block the E1 gate. It does, however, require a fix before PRT-002 approval (reviewer disposition `changes_requested`), because it violates a stated, twice-documented convention on the one file whose diff the reviewer must scrutinize, and it compounds across the remaining tickets.
- **Blocks gate:** No. **Requires fix before PRT-002 approval:** Yes.
- **Discovered during:** PRT-002 independent review (reviewed revision `5288189b73b2fad3709efecf002fef6dcdb24d39`).
- **Evidence:**
  - The plan's File responsibility map ([implementation-plan.md](implementation-plan.md) line 48) states the epic-wide constraint: `index.ts` is **"Explicit public exports only."**
  - PRT-006 Step 8 (line 1435) restates it with rationale: "Update `index.ts` to explicitly export every public constant, schema, predicate, helper, and inferred type from `ids`, `states`, `job`, `events`, `policy`, `artifacts`, `capabilities`, and `version`. **Do not use `export *`; explicit exports make review of wire-surface changes visible.**"
  - Actual PRT-002 `index.ts` (lines 2–3): `export * from "./ids.js";` / `export * from "./states.js";`. The PRT-002 `index.ts` diff therefore shows two wildcards, not the 48 identifiers that became public wire contract; the reviewer had to import the built package to enumerate the actual surface — precisely the review-blindness the convention prevents.
  - `index.ts` is a `Modify` target in **six** tickets (PRT-002/003/004/005/006/007). PRT-003 introduces the **security-critical strict envelopes** (`source.ts`/`job.ts`/`wire-safety.ts`: placement matrix, secret-handle objects). Establishing `export *` at PRT-002 lets those land invisibly in each index diff until a PRT-006 big-bang conversion.
- **Affected tickets:** PRT-002 (fix now); PRT-003…PRT-007 (maintain explicit exports as each module is added).
- **Root cause / resolution:** Replace the two PRT-002 `export *` lines with explicit named exports of the `ids` + `states` public surface — values via `export { … } from "./ids.js"` / `"./states.js"`, and inferred **types** via `export type { … }` (required: the root `tsconfig.json` sets `isolatedModules: true`, so re-exporting a type-only symbol without `export type` errors) — keeping the existing explicit `version` export. The exact 48-name list is already enumerated in the PRT-002 ledger's Delivered scope, so the fix is mechanical. **Counter-reading (noted for the operator):** the "Do not use `export *`" instruction textually sits in PRT-006, and PRT-006's conversion list includes `ids`+`states`, so a "defer to PRT-006" reading is defensible; the reviewer nonetheless requires explicit exports now, per the epic-wide line-48 constraint, the stated review-visibility rationale (which applies at every index diff, not only the last), and to avoid compounding the blindness across PRT-003…PRT-007. The operator/custodian may override to the deferral reading and lock it as a decision. **Resolved in commit `26f6f61d921b3185d4b697e09b45dba27eaec688`** — `packages/worker-protocol/src/index.ts` now uses explicit `export { … }` (50 runtime values) + `export type { … }` (32 inferred types) with no `export *`. Independently re-verified at PRT-002 review attempt 2: the exported wire-surface membership is byte-identical to the pre-fix `export *` surface (built `dist/index.js` runtime keys = `union(version,ids,states)` = the recorded 50-name set; `dist/index.d.ts` re-exports the same 32 types; no private transition-map/guard internals leak), and only `index.ts` + the ledger changed. PRT-002 approved on `26f6f61d9`.
